# v1.7.0 — E10 Phase 2: Stored Deals & DB-Backed Keys

**Released:** 2026-06-10
**Stories:** [RPE-83](https://lowermedia.atlassian.net/browse/RPE-83), [RPE-84](https://lowermedia.atlassian.net/browse/RPE-84) — E10's stateful half
**Gate:** 956 tests / 67 files, lint + typecheck + build green (both release gates riding in `pnpm test`).

## Highlights

The "store once, fetch reports later" workflow: consumers can persist
deals server-side and pull reports by id in any format. Built on the
E11 foundations — the RPE-88 Drizzle schema (Postgres prod / SQLite
tests), the RPE-93 organization model as the consumer identity, and the
RPE-94 tenancy contract (org-filtered queries, existence never leaks).

## RPE-83 — persistence layer

- `deal` table (0003 migrations, both dialects): org-scoped, with the engine's `DealInputs` as opaque JSON — the engine stays the single shape authority. Data-access layer filters `organizationId` in every where clause; cross-tenant access is impossible by construction.
- `api_key` table + `DbApiKeyStore`: the DB is the source of truth while verification stays on RPE-75's sync constant-time hot path via a boot-hydrated mirror; `lastUsedAt` persists in the background; revocation is instant in-process, persisted, and converges across instances via `refresh()` (30 s default interval).
- Idempotent env→DB key migration (`importApiKeyRecords` / CLI `import`) — previously issued secrets keep working; keys gain `organizationId` per the one-identity-layer decision.
- `manage-keys-db.ts` CLI: mint / list / revoke / import.

## RPE-84 — /v1/deals surface

- `POST/GET /v1/deals`, `GET/PATCH/DELETE /v1/deals/{id}` — org from the verified key; env-allowlist keys get an explicit 403; foreign and ghost ids return a byte-identical 404.
- `GET /v1/deals/{id}/report?format=json|csv|pdf` — same negotiation as `/v1/reports`; cached by deal + format + engine version + `updatedAt` (a PATCH rotates the key — structural invalidation); `X-Report-Cache: hit|miss`. Async 202 deliberately omitted (pdf-lib generates in <100 ms) and documented.
- Inputs validate through the shared evaluate validator on write and read-back.
- OpenAPI: six new entries + `StoredDeal` schema under the two-direction drift gate; quickstart gains the stored-deals curl block.

## Operational notes

- New env knobs: `RPE_API_KEYS_SOURCE=db`, `RPE_API_KEYS_REFRESH_SEC` (30), `RPE_REPORT_CACHE_TTL_MS` (600000). The deals surface enables whenever `DATABASE_URL` is set; key storage stays env/file unless opted into the DB.
- Remaining E10 scope: RPE-82 (deploy & secrets) — gated on infrastructure decisions.
