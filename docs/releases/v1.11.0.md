# v1.11.0 — mobile polish: single-document scroll, 44px tap targets, sticky score header

**Released:** 2026-06-17
**Stories/Bugs:** [RPE-101](https://lowermedia.atlassian.net/browse/RPE-101), [RPE-102](https://lowermedia.atlassian.net/browse/RPE-102), [RPE-112](https://lowermedia.atlassian.net/browse/RPE-112)
**Gate:** 965 tests / 68 files (1 env-gated Postgres skip), lint + typecheck + build green.

## Highlights

A mobile-polish release: the evaluator now behaves correctly on phones — one
natural page scroll, properly sized tap targets, and the score stays in view
while editing inputs. Verified at 360–430px; the desktop two-pane layout is
unchanged.

## RPE-101 — mobile double-scroll trap fixed

The root `h-dvh`, plus the inputs `<aside>` and results `<section>` each with
their own `overflow-y-auto`, produced competing inner scroll regions on a
stacked phone layout instead of one natural document scroll. All
viewport-locking is now gated to `lg`: mobile scrolls as a single document
(`min-h-dvh`); at `lg+` the two independent scroll panes are preserved.

## RPE-102 — 44px toolbar tap targets

Header toolbar controls rendered ~28px tall, below the WCAG 2.5.5 / 44px
touch-target guidance. All 13 controls (theme, account, settings, the
Simple/Complex and Screener/Pro-Forma toggles, Save, Deals, Share, CSV, Print,
Reset) now meet a 44×44 minimum on mobile with centered content, reverting to
the compact desktop density at `sm`.

## RPE-112 — responsive verification + sticky mobile score header

Verified the layout at 360–430px across Simple/Complex and Screener/Pro-Forma
(no horizontal overflow). Added a compact, mobile-only **sticky score header**
pinned to the top so the headline Score stays visible while inputs are
scrolled (the whole bar links to the full results); hidden at `lg` and in
Pro-Forma / comparison views. `computeScore()` / `scoreBand()` were extracted
as the single source of truth shared with the existing ScoreCard. The ZIP
field also gained `inputMode="numeric"` so phones surface the number pad.

**Cross-browser note:** verified at representative iOS (390×844) and Android
(360×800) viewport widths via the dev preview; a real-device Safari/Chrome
smoke test on stage is advisable.
