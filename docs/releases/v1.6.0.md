# v1.6.0 — E11: Authentication & Multi-Tenant Accounts

**Released:** 2026-06-10
**Epic:** [RPE-86](https://lowermedia.atlassian.net/browse/RPE-86) — complete (11/11 stories)
**Gate:** 941 tests / 64 files, lint + typecheck + build green. Two release gates now ride in `pnpm test`: the E10 API regression suite and the new E11 auth security gate.

## Highlights

First-party authentication and organization-scoped multi-tenancy across the
TS stack — cookie sessions, email verification, password reset, orgs with
roles and invites, structural tenant isolation, and an opt-in auth UI in the
SPA. Stack per [ADR 0001](../adr/0001-auth-strategy.md): **better-auth**
(pinned minor; email/password + organization plugin only — the api-key
plugin stays off, RPE-75 keys remain the machine credential) over a new
**Drizzle ORM** foundation (PostgreSQL in production, SQLite parity for
hermetic tests).

## Operational notes

- **New env knobs:** `BETTER_AUTH_SECRET`, `DATABASE_URL`, `RPE_AUTH_BASE_URL`, `RPE_AUTH_TRUSTED_ORIGINS`, `RPE_REQUIRE_EMAIL_VERIFICATION`, `RPE_MAIL_PROVIDER`/`RESEND_API_KEY`/`RPE_MAIL_FROM`, `RPE_MIGRATIONS_DIR`, web: `VITE_AUTH_ENABLED`, dev: `RPE_API_PROXY`. The session surface boots **only** when secret + DB + base URL are all set — zero-config key-only deployments are unchanged.
- **Same-origin by design:** cookie sessions require the SPA and API on one origin (Vite `/v1` proxy in dev); the public API's CORS policy stays credential-less per RPE-81.
- **Documented deviation (RPE-92):** better-auth stores reset tokens plaintext in its verification table (consistent with its session-token model). Compensating controls: 24-char random token, 1 h TTL, single-use, request throttling, full session revocation on reset.
- In-memory throttles/limiters require a shared store before horizontal scaling (same caveat as the RPE-76 limiters).
