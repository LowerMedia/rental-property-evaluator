## Highlights

First production release after go-live (v1.8.0 put the new stack on
DigitalOcean App Platform; this release ships on it). Headline is the
location-defaults bug fix that made every ZIP hang on "pending".

## RPE-113 — ZIP→state resolution (the location "pending" bug)

`/region` only derived `stateCode` from the HUD SAFMR call; the ZIP→state
fallback was an unimplemented TODO. With no `HUD_TOKEN` set, every ZIP
returned `stateCode: ""`, so the UI's resolved-state guards
(`LocationInput` `isResolved`, the `Evaluator` sync effect) never fired and
the location sat on "`{zip} pending`" in yellow forever — despite a
successful fetch that applied national-default rates.

- New `@rpe/region-defaults` `stateForZip()` — static ZIP3-prefix → state
  ranges (50 states + DC + PR; military/unassigned bands fall through to
  national).
- `region.ts` derives the state from the ZIP whenever HUD doesn't resolve
  one, so location resolves to **state-level** defaults for any valid US
  ZIP, independent of HUD. HUD stays authoritative for ZIP-level rent +
  town/county label when a token is present.
- Reminder: location defaults are a **simple-mode** feature — they drive
  the hidden tax/insurance/vacancy baselines (visible in the results), not
  complex-mode inputs.

## RPE-114 — header wraps on narrow viewports

The app header laid title + controls in a single non-wrapping row; it now
`flex-wrap`s so controls don't crowd/overflow on small screens.

## RPE-115 — dev env for VITE_APP_ORIGIN

Committed `apps/web/.env.development` so `pnpm dev` resolves the
`%VITE_APP_ORIGIN%` placeholders in index.html (previously defined only in
`.env.production`, which dev mode doesn't load) — silences the 15
"not defined" warnings. Production build path unchanged.

## Operational notes

- Optional `HUD_TOKEN` on the prod api adds ZIP-level rent + nicer labels
  on top of the now-working state resolution.
- Local dev: run the api as a second process (`/region`, autofill, auth all
  need it); a local Postgres via Docker is the simplest DB
  (`apps/web/.env.local` → `VITE_AUTH_ENABLED=true` to exercise auth).
