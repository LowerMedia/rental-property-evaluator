# Release notes — v1.3.0

**Released:** 2026-06-09
**Tag:** `v1.3.0`
**Quality gate:** lint, typecheck, tests, build all green — 651 tests across 26 files (up from 461 / 14 at v1.2.0)

v1.3.0 turns the evaluator from a calculator you fill in by hand into one that fills itself in: paste an address to autofill the deal, flip to Simple mode to hide everything but the essentials, and set a location to replace national baseline assumptions with regional averages.

## E7 (core) — Address autofill via RentCast — RPE-43

The remaining E7 stories (URL parser, comps & history, scrape/paste fallbacks — RPE-44–54) continue in a later release; the epic remains open.

- **`@rpe/rentcast`** — typed RentCast HTTP client with `PropertyData` normalization; addresses are redacted from error messages.
- **`POST /property`** proxy endpoint in `apps/api` — API key stays server-side; CORS handled; error responses sanitized (no upstream `err.message` forwarded); rate limits surface as 429.
- **Connector settings UI** — RentCast API key stored in `localStorage`, masked display, modal focus trap, full a11y pass.
- **AutofillBar + preview popover** — `useAutofill` hook with abort-on-unmount; fetched values are diffed against current inputs and previewed before applying; user-edited fields are never silently overwritten.

## E8 — Simple / Complex mode switch — RPE-55 (RPE-57–62)

- **Mode state model + tiering config** — every input and result classified simple vs complex.
- **Baseline-assumptions module** — hidden simple-mode inputs (vacancy, CapEx, maintenance, management, insurance, closing %) are filled from documented baselines feeding the unchanged engine.
- **Simple-mode form and reduced KPI set** — cash flow, cap rate, cash-on-cash, 1% rule.
- **No value loss on switching** — complex→simple keeps entered numbers; simple→complex reveals all fields pre-filled with the baselines in effect.
- **"Based on assumptions" badges** on assumed/derived fields.
- Engine-parity tests guarantee simple mode computes identically to complex mode with the same effective inputs.

## E9 — Location-based assumption defaults — RPE-56 (RPE-63–67, RPE-72)

- **Research spike (RPE-63)** — settled sources and granularity: Census ACS property-tax rates, NAIC insurance averages, HUD SAFMR rents; state-level granularity with a national fallback chain.
- **`@rpe/region-defaults`** — static per-state regional rates package.
- **`GET /region`** endpoint in `apps/api` — resolves ZIP → region with HUD SAFMR rent integration, 10s upstream timeout, metro-wide FMR area support.
- **LocationInput** — ZIP entry (ZIP+4 accepted) with resolved-region chip, spinner while resolving, and explicit "couldn't look up" feedback (role=alert) on failure instead of a forever-pending state.
- **Location-aware baselines** — when a location is set, regional averages replace the static baselines feeding simple mode; a user override always wins; source/region badge shows where each rate came from (e.g. "TX state averages (Census ACS / NAIC 2022)"). Clearing the location reverts to national baselines.
- **30-day response cache (RPE-72)** — `/region` responses cached in `localStorage` under `rpe_region_${zip}` with a versioned envelope; corrupted/expired/foreign entries and unavailable storage degrade safely to a refetch; failures are never cached.
