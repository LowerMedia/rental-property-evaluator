# Release notes — v1.5.0

**Released:** 2026-06-09
**Tag:** `v1.5.0`
**Quality gate:** lint, typecheck, tests, build all green — 878 tests across 52 files (up from 799 / 43 at v1.4.0)

v1.5.0 is the Public REST API release: the apps/api server grew from an internal SPA proxy into an authenticated, rate-limited, documented `/v1` surface that external services can call for evaluations and reports in JSON, CSV, or PDF.

## E10 (Phase 1 code-complete) — Public REST API — RPE-73

- **API foundation (RPE-74)** — minimal exact-path router replaces the ad-hoc dispatch; all legacy routes alias under `/v1` unchanged; `X-Request-Id` on every response (echoed when sane, generated otherwise) and in error bodies; structured per-request log lines; `GET /v1/health` with API metadata. `/v1`-native errors use the standard `{ error: { code, message, requestId } }` envelope while legacy flat shapes are preserved for the SPA.
- **API key auth (RPE-75)** — `rpe_live_…` secrets sha256-hashed at issuance (shown once by `scripts/manage-keys.mjs`, unrecoverable after); env/file/config-backed store; constant-time verification; Bearer + `X-API-Key`; revocation; key id (never the secret) in request logs. Enforced on `/v1` only when keys are configured — zero-config dev unchanged.
- **Rate limiting (RPE-76)** — per-key throttle with per-IP fallback; `X-RateLimit-Limit/-Remaining/-Reset` on every `/v1` response; 429 + `Retry-After`; `RPE_V1_RPM` (120) / `RPE_V1_DAILY_CAP` (10000). In-memory windows — Redis required before horizontal scaling.
- **Headless report module (RPE-77)** — `@rpe/report`: canonical JSON report (config-annotated metrics with signals, ScoreCard-consistent score, pro-forma when present) + DOM-free CSV; the UI re-exports the shared serialization (golden parity locked).
- **PDF pipeline (RPE-78)** — programmatic pdf-lib rendering of the canonical report (deal summary, score, metrics with PASS/FAIL, pro-forma table, pagination); byte-deterministic for a fixed `generatedAt`; trade-off vs HTML-to-PDF documented.
- **Public endpoints (RPE-79)** — `POST /v1/reports` with format negotiation (`?format` > body > `Accept` > json; 406 otherwise) and attachment filenames; input validation extracted into `validateEvaluateBody()` shared with `/v1/evaluate`.
- **OpenAPI + docs (RPE-80)** — 3.1 spec at `GET /v1/openapi.json`, interactive reference at `GET /v1/docs` (Scalar CDN, zero deps), `docs/api-quickstart.md`; spec ↔ routes drift CI-gated in both directions.
- **Hardening (RPE-81)** — CORS policy (credential-less `*` default, `RPE_CORS_ORIGINS` allowlist with origin echo + `Vary`; `Allow-Credentials` never sent), `nosniff`/`Referrer-Policy` everywhere, `no-store` on `/v1`, fuzz/abuse battery (envelope always, stack traces never), consolidated contract suite.
- **Test harness + release gate (RPE-85)** — `startTestApi()` in-process harness with authed client and CSV/PDF asserts; golden Example-deal regression suite rides in `pnpm test` so a red API suite blocks every future release; convention in `docs/api-testing.md`.

## Not in this release (gated)

- **RPE-82 (deploy & secrets)** — needs hosting/credential decisions.
- **RPE-83/84** — explicitly Phase 2 (persistence, stored deals).
- **E11 (auth & multi-tenant, RPE-86+)** — gated on the RPE-87 auth-strategy SPIKE decision.

The E10 epic (RPE-73) stays In Progress accordingly.
